# S3 0.4.0-beta.1

Original LILYGO T-Dongle-S3 only (16 MB flash, no PSRAM). This beta extracts
shared reliability fixes from C5 branch `f09a946` onto Rust integration base
`bf18c5e`. It is a prerelease of the Rust firmware, not the stable C release.

Changes:
- Try other saved profiles after a visible preferred profile fails, including
  directed attempts for hidden profiles. Reuse the existing bounded reconnect
  policy (1, 2, 4, 8, 16, then 30 seconds). A profile-selection request interrupts
  the retry wait. Healthy connections do not continuously scan or rotate.
- Serve an explicit scan request even when no profiles are saved.
- Record known radio disconnect reasons and retain the driver's reason text.
- Discard partial console commands on transport read errors.
- Use the destination IP's ARP entry for routed-mode replies, and reject short
  packets before reading the destination. The L2 bridge remains single-host.
- Report actual recovery mode on the display.

C5 pins, PSRAM allocation, serial-IP/VpnService and wireless gateway mode are
not part of this backport. The S3 tailnet build permits one active membership.
The unused C5 text-row helper was not imported into the S3 renderer.

## Reproduce

Use the pinned espup 0.17.1 / Xtensa Rust 1.97.0.0 toolchain documented in
`rust/rust-toolchain.toml`, espflash 4.6.0 and a host Rust toolchain (validated
with 1.98.1). Source the espup export file and put espflash on PATH first.
From the repository root:

```sh
export CARGO_TARGET_DIR="$HOME/.cache/cargo-target"
export TDONGLE_VERSION=0.4.0-beta.1
(cd rust && cargo +1.98.1 test --locked --workspace -- --test-threads=1)
bash rust/tools/build.sh
bash rust/tools/build_tailnet.sh
python3 rust/tools/package.py "$TDONGLE_VERSION" \
  rust/dist/tdongle-rust-0.4.0-beta.1-tailnet/app-tailnet.bin \
  rust/dist/tdongle-rust-0.4.0-beta.1-tailnet/tdongle-fw.elf \
  rust/dist/s3-beta-tailnet/tdongle-s3-0.4.0-beta.1-tailnet
```

Both build scripts use locked firmware dependencies. The bridge build also
produces a diagnostic image. The tailnet build checks stack frames, direct-call
chains, DRAM budget, boot ordering and the ELF hash embedded in the image.
Build and test results belong in the release's `BUILD-EVIDENCE.json` and logs;
host tests and static memory checks do not establish hardware compatibility.

## Install and recover

Choose **bridge** for the single-host USB-NCM adapter, or **tailnet** for the
image with optional routed tailnet mode. An existing saved mode remains in NVS;
installing an image does not select tailnet mode automatically. `app-diagnostics.bin`
is for bridge measurements, not a network-only USB descriptor variant.

Verify the archive checksum and its internal `SHA256SUMS`. App-only updates use
**0x20000**, and require the matching factory-nvs-v1 partition layout. Preserve
NVS; do not erase flash for a routine update. Full packages also contain the
pinned rescue bootloader (0x0) and partition table (0x8000). Check the existing
layout before writing either. Back up working configuration and retain a
known-good firmware package for rollback.

The repository's `rust/tools/flash.sh` is pinned to a development board MAC and
macOS port conventions: it is not a generic flasher. On other hosts, explicitly
select the original S3's port in esptool. Hold BOOT while plugging in to enter
ROM download mode, release BOOT, then use `--chip esp32s3 --before no_reset`.
Use the pinned tool's `--after watchdog_reset` behavior documented by the project;
`hard_reset` has re-entered download mode on the development board. Never apply
these images to the C5. No automatic flasher or stable browser installer is
updated by this beta release.

## Physical acceptance still required

No new hardware tests qualify this beta. Check enumeration, both traffic
directions, wrong-password failover, missing/hidden APs, AP restart, explicit
profile switching, console reconnection, display recovery status and sustained
traffic. Verify the actual TeslaAndroid image and its downstream AP separately.
No claim of throughput, Internet reachability or TeslaAndroid compatibility is
made by a successful compile or host test.
