# Bounded upstream DNS concurrency execution

Aim: reduce the measured upstream-busy rejection bottleneck while preserving responsive tailnet-local lookup and limited SRAM/socket resources. Evidence: 0.2.19 handset recorded 388 upstream busy rejections; this is not proof every rejection caused user-visible failure. Scope is DNS transport and numeric diagnostic counters. No flash layout, credentials, routing, bridge, or USB ownership changes.

Delivered: four pending upstream transactions on one connected UDP socket in the existing DNS task. Fixed tracking table is under 192 bytes; one shared existing packet buffer. Rewritten 16-bit IDs disambiguate client ID collisions and wrap; reply question hash must also match. Connected socket pins resolver source. Responses restore original IDs and go to the saved client port. Polling drains at most four responses per loop; local names never wait behind upstream receive. Pending slots expire in two seconds and idle socket closes. Full capacity returns transient SERVFAIL. Resolver address changes close old socket and invalidate pending records. No additional task or per-query heap allocations.

Saved counters add upstream_forwarded, upstream_replies, upstream_timeouts and upstream_pending_peak; Android strict numeric allowlist and serialization tests preserve these alongside existing counters. Retention is bounded and does not save domain strings.

Risk retirement: ASan/UBSan production-code tests force four simultaneous same-ID client requests with different client ports, reversed replies, mismatched question rejection, ID wrap, exhausted table, two-second expiry and socket cleanup, connect/send failures, and local success while upstream slots are occupied. These fail the tempting alternatives of simply raising socket count or forwarding replies by original transaction ID. Fixed table size assertion fails unbounded packet buffering. Existing DNS cache/session/generation/TTL and startup cleanup tests still pass. Full host suite passes; firmware and Android build/unit/lint/hash/signing checks recorded with packaged artifacts. Fresh diff review performed; sg unavailable.

Review: aligned, bounded. Four is an explicit capacity rather than a claim that saturation is impossible. Ordinary DNS response caching and TCP/truncated-response fallback are outside this concurrency fix. Remaining handset saturation and long-uptime RAM behavior need runtime evidence; cannot be verified through host mocks. No hardware flash performed by the agent. Stop/pivot if new counters show persistent four-slot saturation or RAM deterioration; then consider bounded duplicate coalescing or TTL-aware ordinary DNS caching based on query evidence.
