# DNS reliability execution and review

Aim: stop intermittent local tailnet name failures without duplicating the flash peer directory or adding task stacks. Scope: gateway DNS and saved boot counters; preserve USB ownership, bridge mode, identities, flash layout, and existing routing. No physical flashing or destructive changes.

Delivered: local tailnet queries no longer wait behind a two-second blocking upstream receive. One outstanding upstream socket is polled nonblocking by the existing DNS task; excess upstream requests get SERVFAIL and may retry. Four positive MRU entries (under 640 bytes) expire after 30 seconds and require a connected membership, valid session, matching membership ID and directory generation. No negative cache. Generation changes during a scan fail transiently. Temporary lock/session/storage/alias failures return SERVFAIL; confirmed absent A names return NXDOMAIN. Non-A local queries return empty NOERROR so IPv6 queries cannot incorrectly negate a valid IPv4 name. Wire answer TTL remains 30 seconds.

Counters in saved boot health: queries, cache hits, lock failures, temporary failures, absent names, upstream busy rejections (field upstream_busy_drops retained as a counter name), and maximum lookup ticks. This measures lookup duration, not Android resolver queue latency. No extra tracing buffers or per-query heap allocation.

Risk retirement: production-source ASan/UBSan DNS tests reject the tempting cache-only fix by forcing disconnected state, lock failure, flash-read failure, map generation change during scan, generation invalidation, TTL expiry, membership removal, and real MRU eviction. Tests force stalled upstream receive while a local answer succeeds and verify two-second socket cleanup, busy upstream SERVFAIL, malformed packet bounds, and startup allocation/socket/bind/task/socket-option failure cleanup. Existing full host suite verifies shared routing/USB/storage behavior. Fresh diff review performed; sg unavailable. Hardware Android resolver behavior and hours-long memory/heat trends remain accepted with rationale: require the handset/dongle, unavailable for agent-controlled flashing. Do not claim these observations prove the original failures were exclusively DNS-server bugs; counters will distinguish future cases.

Review: aligned with original aim. No extra worker stack or app-side peer directory. Cold lookup still scans flash under the membership lock; the bounded cache removes repeated hot-name scans rather than changing directory ownership in this patch. Upstream concurrency is deliberately one to retain socket and RAM bounds; explicit busy responses replace silent waiting. A separate upstream queue would increase RAM and is outside this focused change.
