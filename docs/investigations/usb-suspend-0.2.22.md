# USB suspension clarity and evidence

Aim: distinguish configured-but-suspended USB from an unconfigured host without claiming Android screen-off causality. Existing tud_ready equals mounted and not suspended, so the previous single boolean could not distinguish these states. Scope: LCD state/copy and bounded saved boot-health telemetry, not transport policy, wake locks, resets or remote-wakeup attempts.

Delivered: both unified modes show USB suspended when mounted and suspended, waiting for USB host when unconfigured, and normal readiness when resumed. Tailnet readiness remains independent. Strong TinyUSB suspend/resume callbacks record only counters, uptime timestamps and last suspend remote-wakeup permission in fixed20-byte atomic storage. They perform no allocation, I/O or reset and do not override mount/unmount callbacks owned by esp_tinyusb. Current configured/suspended/ready flags and callback counters enter serial and HTTP boot health; Android strict numeric/boolean allowlists retain them in saved/uploaded payloads. Counters are since boot; timestamps are uint32 uptime milliseconds. They establish USB events, not why Android initiated them.

Risk retirement: production callbacks tested for repeated suspend/resume, remote-wakeup permission changes, timestamps and configured/readiness flags; 10,000 cycles retain exact20-byte storage. LCD tests force suspended, unconfigured and resumed states in bridge and ready-tailnet modes and preserve tailnet readiness; raster bounds and existing DMA failure ownership tests pass. Android serialization tests retain all eight fields, reject credentials/coerced booleans/negative counts and accept older missing objects. Full host tests and builds verify integration; root and alternative CMake sources include callbacks. Hardware screen-off correlation and suspend/resume behavior require runtime captures; no physical flash by agent.

Review: aligned; no attempt to keep Android awake or initiate USB wake. No extra diagnostic ring or task. False waiting message is corrected only where actual configured+suspended evidence exists. No routing, identity, NVS or flash layout changes. Commit-signing configuration unchanged; unsigned commit allowed for this reversible local change if 1Password remains unavailable.
