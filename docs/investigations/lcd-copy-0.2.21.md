# LCD message clarity execution

Reader: owner glancing at the original 160x80 dongle screen. Job: identify current state and the next useful action. Style: short operational text, concrete verbs, no unsupported connectivity claims. Scope: every state of the unified firmware LCD (both bridge and tailnet modes). Legacy standalone UI is not used by this firmware and is unchanged.

Changes: connecting says Joining your tailnet / Please wait; failed connection says Tailnet connection failed / App: Networks for details; first Wi-Fi setup names App: Networks and Add a 2.4 GHz network; saved Wi-Fi says Trying saved Wi-Fi; browser approval explicitly says Approve login and names Networks sign-in; recovery names Overview and the actual Restart services button; bridge reports Wi-Fi association and USB-host connection separately without claiming internet verification; ready state retains 0/1/N membership counts; disconnected membership names Reconnect; install names Installing firmware and Keep USB plugged in; startup names Starting dongle services. Footer USB NOT READY replaces vague WAIT. Partial readiness directs to Networks for details only when a USB host is ready; otherwise it reports waiting for USB host.

Verification: production composer tests enumerate 2048 boolean/state combinations, enforce 13-character title and 26-character line limits, preserve recovery/install/sign-in priority, test first vs saved Wi-Fi and bridge host readiness, keep counts bounded, check scanline canaries and DMA failure buffer ownership. Rendered connecting and multi-tailnet frames inspected at exact 160x80 size. No new heap allocation or framebuffer. Firmware build and Android packaging tests/hashes/signing run. Hardware legibility remains a handset/dongle observation; no physical flash performed by the agent.

Review: aligned with writing-without-bullshit and style: vague destination nouns become exact app locations/actions; progress is named as a state; uncertainty is preserved for unverified internet and USB host readiness. No state-machine change, new services, credentials, layout or routing change. Full host checks plus bounds/raster checks reject the tempting string-only patch that clips text or claims routing before readiness.
