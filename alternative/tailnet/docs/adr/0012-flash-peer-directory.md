# Flash peer directory and lazy peer activation

The original ESP32-S3 board has no PSRAM. Its 16 MiB flash had 11.875 MiB unallocated, while semantic maps staged peer updates in RAM and rejected any section exceeding eight records. A tailnet's discoverable peers must not be limited by the active WireGuard working set.

Allocate a 4 MiB FAT/wear-levelled data partition at 0x420000. Preserve NVS at 0x9000, PHY at 0x19000, and the existing factory app at 0x20000. The remaining 7.875 MiB stays unallocated. Each membership's directory is named using its full public node key; it contains no private keys. Initial maps stream into one-record scratch storage and a disk operation journal. Complete, validated maps produce a checksummed, synced generation; two snapshot banks retain the previous complete generation on a failed write. Boot validates both banks. Saved records do not authorize a session: a current authoritative map must be committed before activation.

Keep the existing eight-slot working set per admitted active membership. Map discovery does not populate it. Outbound USB packets and authorized inbound relay/discovery traffic activate peers on demand. Recent use protects peers for ten seconds; pressure evicts the least recently used idle peer, preserving the configured priority peer. At most four outbound packets per membership, each at most 1400 bytes, wait up to five seconds for a handshake. Exhaustion rejects admission rather than evicting recently used traffic. Active memberships continue to be admitted by actual heap and socket resources; there is no product limit of two memberships.

DNS reads names from the flash directory; setup displays eight records per page. USB aliases use a checksummed append-only flash file, retaining a 64-entry RAM cache. Existing NVS aliases migrate without address changes. A monotonic NVS reservation advances before a new alias is exposed, so interrupted writes cannot recycle an address. Cold routing runs on a bounded worker queue, outside lwIP callbacks. Generation reconciliation removes revoked keys and changed routes from the working set. Public-key rotation removes the old encrypted session.

Increasing all peer runtime arrays was rejected because it couples RAM to tailnet size. Re-fetching the full map on each miss was rejected because the documented control request has no destination-specific lookup and incremental patches require retained base state. A mandatory external gateway was rejected because it changes onboarding and requires additional infrastructure.

## Accepted limitations and measurements

The operation journal is transactional staging, not a long-lived delta log. A changed map writes a replacement snapshot; a 1000-peer snapshot is roughly 281 KiB with the host's 288-byte record layout. Keepalives and maps without peer changes do not open a staging transaction. Snapshot copying and flash write amplification are explicit first-version costs. Measure actual update frequency, cold latency, and wear-levelled storage costs on the board; sustained churn requires an append/compaction design before production qualification. Host filesystem failure injection does not prove FAT metadata survives every electrical power-loss pattern. Actual routing, two simultaneous memberships, and physical resource headroom require device tests. Firmware remains an experimental preview.

The shared parser workspace shrinks by 8192 bytes. The production map path removes the old 32-record RAM staging and peer-sized batch allocation. The live eight-slot runtime array remains bounded per membership; FAT resources and a routing worker consume some of the recovered memory. Do not claim an 8192-byte net free-heap improvement without a device measurement. Existing small membership metadata and diagnostic NVS journal already persist in flash; no additional bulk RAM store was found to relocate. Live keys, replay state, packet queues, task stacks and flow tracking stay in RAM.

## Amendment: activation on an unauthenticated claim (PR 27)

A DERP RecvPacket's source key and a DISCO sender key are claims, not proof, so the "authorized inbound" activation above is conditioned. A DERP packet from a non-resident key is dropped before any flash read unless it is a WireGuard initiation with a valid mac1 for our key; it then takes the membership's single trial slot (peer idle for six times the ten-second window to be evicted, five seconds to authenticate, thirty seconds of cool-down after a failed trial, three-lookup token burst refilled one per second). The peer becomes ordinary only when WireGuard reports a session key for it. A DISCO sender activates only after its box opens with the directory record's disco key, and is rate limited by the same tokens. Consequences accepted: whoever can inject DERP frames can keep the trial slot busy and delay inbound activation of a new peer (outbound traffic and DISCO are unaffected), and a replayed captured initiation or DISCO packet can make a genuine directory peer resident.

## Amendment: control server key (PR 27)

The compiled Tailscale key is used for SaaS and nothing is fetched. A custom login server's Noise key is pinned (`ctrl_noise_key`, any scheme, never dropped) or fetched from `/key`: over verified TLS for `https://` (the default for a bare host), or in the clear for an explicit `http://`, as Tailscale's client allows. A plaintext-fetched key is unauthenticated, is reported as `control_key_auth=4` and logged, and the gateway never sets a custom login server itself. A fetched key is a cache: after two consecutive Noise handshake failures it is dropped and fetched again before the next attempt, with drops spaced 30 s doubling to 10 min.
