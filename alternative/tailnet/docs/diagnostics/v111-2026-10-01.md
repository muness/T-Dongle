# Diagnostic retention update: APK v111 / firmware 0.2.7

## Why this changed

The v110 archive captured Android's USB Ethernet interface and routes, but the app retained only `SocketException`; it could not say whether the dongle refused, reset, or never received `/status`. The saved v110 archive is preserved locally at `local-diagnostics/tdongle-v110-2026-10-01-after-repro.json`. Raw captures stay uncommitted because they include device and network metadata. The sanitized capture analysis is in `v110-2026-10-01.md`.

## Firmware journal

Firmware 0.2.7 stores the newest eight diagnostic events in an NVS blob under `tn_diag`. The bounded journal survives reboot and USB disconnect. It records registration failures, map failures, and successful connection transitions with uptime, membership ID, state, map attempt/byte/error counters, numeric HTTP/2 close error and stream, and internal free/largest-block memory. Repeated identical adjacent events are suppressed for 30 seconds. The writer uses a nonblocking mutex and performs NVS work after map processing has released its shared workspace lock.

The local USB endpoint `GET /diagnostics` streams this ring without allocating an unbounded response. `GET /status` now also exposes `h2_error` and `h2_last_stream`. The journal stores numeric codes only; it does not persist auth URLs, keys, peer names, or response bodies. Eight records use under 0.5 KiB of NVS payload and no growing firmware-side log buffer.

## Android capture

APK v111 keeps the existing automatic local rolling archive: one sample every two seconds, ten-minute retention, and an 8 MiB cap. Every sample now contains bounded USB setup events with HTTP stage/path/method, selected Android network and interface, local addresses/routes, elapsed time, response byte count, exception class, and a safe cause category. It also reads firmware `/diagnostics` and saves those events alongside `/status`; thus a later status failure does not erase the dongle's earlier journal. Raw exception messages and response bodies are excluded.

After reproducing, unplug the dongle, let Android regain Wi-Fi, then fetch the phone debug root or use Help → Diagnostics → Export saved diagnostics. A computer may not be able to reach the phone while Android is using the USB Ethernet link. The complete v110 captures remain available only on the development machine under the ignored `local-diagnostics/` directory.

## Build and evidence boundary

Firmware 0.2.7 compiled and packaged successfully for ESP32-S3. The image is 0x10d420 bytes; 74% of the app partition remains free. APK v111 compiled and assembled with the 0.2.7 image embedded. No physical board validation is claimed. The next capture should distinguish a USB request failure from registration/map failure and preserve numeric GOAWAY/RST_STREAM reasons if the map exchange is reached.
