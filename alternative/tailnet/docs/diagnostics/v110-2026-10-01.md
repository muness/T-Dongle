At root-capture time the dongle was unplugged and no USB device was enumerated. This capture does not establish whether firmware 0.2.6 fixed the map disconnect: no map request was observed on 0.2.6.

The screenshot's “USB setup request failed: SocketException” is consistent with the same Android-to-dongle HTTP reachability failure seen in the status polls. The app reports only the exception class, not the socket's cause, so the archive cannot distinguish refusal, reset, or route failure. Do not attribute this screenshot to airplane mode; the captured Wi-Fi was active and validated.

## Retrieval constraint

The phone's diagnostic HTTP service runs on the phone. When Android switches to the dongle's USB Ethernet network, a computer on the phone's Wi-Fi may not be able to route to the service. Do not expect to retrieve the service while the phone is attached to USB Ethernet. The app already saves a rolling ten-minute, 8 MiB-bounded archive locally every two seconds while USB is attached. After reproducing, unplug the dongle, wait for Android to return to Wi-Fi, then retrieve the root URL or use Help → Diagnostics → Export saved diagnostics. Fetch only after the phone is reachable again.

## Closer source and timeline comparison

The four readable samples in the second archive occur at offsets 0, 2.12, 4.14 and 6.17 seconds. Only the first three have the membership enabled; it is already disabled in the fourth, before the first socket failure at 8.19 seconds. All four have zero startup heap counters and omit live-client map diagnostics. They report approximately 153 KiB free memory and a 110592-byte largest block. Thus the earlier wording that all four showed an enabled membership, or that disabling was observed only after the HTTP failures, was imprecise. This sequence does not record a started membership or demonstrate a new map failure.

[The control-path dissent](../control-path-dissent-2026-10-01.md) records independent actionable findings from source and local reproductions: partial proactive Noise records are discarded by the current reader, the old duplicate SETTINGS-ACK sequence produces a Go HTTP/2 protocol error, and the gateway's descriptor budget can exclude management connections at two active memberships. These defects do not prove the cause of this specific no-client HTTP failure; socket occupancy, startup transitions and reset evidence remain absent from this archive.
