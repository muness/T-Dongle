# Startup transport and eight saved Wi-Fi networks

Aim: recover startup without opaque retry loops and restore eight saved SSIDs with strongest-signal boot selection and roaming. Preserve flash layout, identities, the working data plane, and management availability.

The observed 4093-byte Noise error is a body-read failure, not receive-capacity rejection. The existing reader already handled prefixes; this change consolidates it into one cursor/deadline with fatal partial-record failure. It preserves expected/received lengths, elapsed time, errno and raw TLS result across successful retries. A compact last-body-failure record is saved alongside the existing flash journal and returned by diagnostics, so Android's automatic archive can retain it after reboot. This identifies the remaining physical failure rather than asserting its upstream cause has been fixed.

Wi-Fi stores eight credential profiles in its own versioned NVS blob, updates an existing SSID in place, refuses a ninth, and supports removal. It imports the tailnet build's single credential and valid original-bridge profiles when the new blob is absent; original namespaces remain untouched. Settings corruption fails closed. USB setup lists saved SSIDs and offers removal; adding a network no longer replaces the previous one. Passwords never appear in status or diagnostics.

The existing manager scans at boot, every ten seconds while offline, and every minute while online. Scans consume AP records one at a time. Boot chooses the strongest eligible saved SSID; disconnected joins use a sixty-second cooldown and hidden-network round robin. Connected roaming requires a weak current signal and at least a 12 dB advantage. Scanning and configuration run outside the event callback and membership lock. Management stays available if directory/routes fail; membership activation retains its independent route guard. Reusing the existing manager avoids another 4 KiB task stack. Recovery quarantine still pauses automatic services.

Risk retirement: exact production-reader tests fragment the 4093-byte body, inject transient waits, EOF, permanent TLS failure and deadline exhaustion, and retain evidence after success; a timeout-only patch or a restarted cursor fails these checks. Existing Noise/H2 tests require no nonce advance on truncated/authentication-failed frames. Production Wi-Fi storage/maintenance tests cover eight profiles, overwrite, ninth rejection, reload, persistence failure, removal, legacy import, strongest-of-eight selection, cooldown fallback and no healthy-link churn. Existing startup fault injection preserves USB/HTTP and independently gates routing. Existing socket/DERP/flash-directory ownership tests cover bounded cleanup. These checks do not prove real AP roaming or eliminate upstream coordinator closure; board startup, heap high-water and peer traffic remain hardware acceptance. No physical flash or storage erase is performed.

Review: no receive-buffer expansion, relaxed membership memory guard, changed flash partition, or Android routing dependency. The sg CLI is unavailable; fresh diff inspection and host sanitizer tests are used. A future background diagnostics service and permanent Mac receiver supervision are separate work.
