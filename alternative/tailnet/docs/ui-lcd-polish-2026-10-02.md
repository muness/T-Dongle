# Setup and LCD polish

The explicit user scope is every Android screen and the original dongle LCD. This pass preserves saved identities, Wi-Fi configuration, flash layout, routing semantics and USB interface ownership. Readiness remains gated by the live routing state; a saved peer list or assigned address is not evidence of working traffic.

The setup page removes the USB-address explanation from the primary flow, uses the reported tailnet identity when available, preserves expanded sections across polling, groups peer names and IPs into compact rows, and exposes Wi-Fi discovery. Raw protocol errors remain in connection details. The Android USB bridge now allows the firmware's existing GET /wifi-scan endpoint and gives it a bounded 15-second read timeout.

The LCD reuses the original board's ST7735 pins, orientation and initialization. It allocates a single 160-pixel RGB565 scanline statically, with no framebuffer or separate task. The existing control task refreshes it, including recovery when the membership manager does not start. It samples memberships under their mutex and releases that mutex before any SPI wait. One outstanding DMA transfer owns the scanline. Failure or timeout disables rendering without freeing/reusing an in-flight buffer. Partial initialization releases resources before DMA starts. Display faults remain in boot diagnostics but do not mark networking as paused.

Validation uses the real portable state composer and scanline renderer under ASan/UBSan, with 0/1/N memberships, absent Wi-Fi, pending sign-in, partial readiness, startup, recovery, installation and bounded long labels. Pixel canaries protect every row. A harness extracts the production transfer loop and verifies unchanged-frame suppression plus error/timeout behavior. Startup injection confirms display failure does not prevent later network services. Boot-health tests distinguish a display-only fault from required service recovery. The complete gateway host suite and ESP-IDF build are required for the packaged revision.

Manual review: the renderer adds SPI initialization allocations, so the 320-byte scanline is not its total runtime cost. The app's current-state wording does not claim end-to-end reachability. The existing board profile is reused but actual panel orientation, electrical behavior, USB permission flow, physical flashing and sustained peer traffic remain hardware acceptance boundaries. No board was flashed for this pass.
